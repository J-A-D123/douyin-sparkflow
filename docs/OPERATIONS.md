# 运行与故障处理

## 开始前

使用 Python 3.10+，或按 README 通过 Docker Compose 部署。首次安装默认每天 12:00，时区默认 Asia/Shanghai。已有配置和定时文件由安装器保留，不会被升级模板覆盖。

先确认一个账号和一位明确选择的好友：正常扫码、保存、刷新好友、勾选目标、保存。账号之间使用独立浏览器资料。重新登录时如果抖音号与原记录不同，将拒绝覆盖原账号及联系人；手机上切对账号后再试。字母数字抖音号会保留完整内容，不会只留下数字后缀。

默认入口与发送适配器为普通聊天页 `https://www.douyin.com/chat`（`browserChatInterface: ordinary`）。好友刷新读取该账号的现有会话；它不是完整好友关系扫描。没有出现在会话中的好友，请先由本人在抖音正常聊天中建立会话。同名联系人无法唯一确认时停止，不能猜测发送对象。

发送在 `login-desktop` 的可见浏览器中执行，调度器与管理服务只传递已保存账号和目标的引用，不在请求中传输 Cookie。内部令牌与持锁任务的随机租约共同限制派发。正常登录、验证码或安全验证由本人完成；程序不会解题、改写平台检查结果或转用代理绕过限制。“自动发送已暂停”是本程序的保护状态，不表示抖音账号被封禁。原始错误可以展开“查看诊断信息”。

需要单独核验发送浏览器时，先暂停任务，再在项目根目录执行 `docker compose exec login-desktop python -m scripts.verify_sender_desktop`，随后打开本机 8788 登录桌面。脚本持有任务锁，禁止自动发送，只有页面中的本人抖音号与保存账号一致时才保存会话。多个账号时需用 `--account-ref` 选择一个。平台出现验证时由本人操作。

## 时间与运行状态

面板中的“保存时间”只修改计划；“启动自动任务”才启动调度服务。首页会区分运行、暂停和状态未确认。也可在项目根目录运行：

```sh
docker compose up -d --no-build --no-deps web login-desktop
docker compose start scheduler
docker compose ps -a
```

固定每日任务在错过时间、系统唤醒或服务恢复后会补查当天一次。调度器先把本次启动写入 `state/cron/.sparkflow-cron-state.json`，避免同日重启反复启动；账号发送层还会跳过当天已确认及结果不明的目标。高级窗口仍按原窗口规则执行，不会把每个错过的分钟都补跑。

调度记录只证明任务已启动，不证明消息送达。启动后失败、崩溃或账号过期不会被伪装成成功；查看发送控制台处理具体目标。

## Mac 挂机

可选辅助服务只在“接电 + 调度器运行”时防止空闲休眠，屏幕仍可关闭；拔电或暂停调度后释放保持唤醒的请求。合盖、关机、退出登录、Docker 未运行时不能保证准点执行。它不修改系统的电源偏好。

在 macOS 项目根目录明确安装或卸载：

```sh
python3 deploy/install-macos-keepawake.py install
python3 deploy/install-macos-keepawake.py status
python3 deploy/install-macos-keepawake.py uninstall
```

## 发送状态

| 状态 | 含义与处理 |
|---|---|
| 网页发送确认 | 普通聊天获得明确业务成功状态和服务器消息编号，并在全新上下文的服务器聊天记录中核对同一编号、己方身份、正文与创建时间，无明确失败或可见范围限制。历史扩展字段原样保留。不能单独证明 App 收件或火花延续；当天自动任务跳过。 |
| 待核验 | 发送已开始，但无法确认结果。可能已送达；自动任务不再重复。先检查双方聊天记录，再决定是否手动重试。 |
| 发送前失败 | 例如编辑器未接受内容、会话对象不匹配；发送动作尚未开始。修复后可以明确手动重试。 |
| 登录失效 | 在本人 App 和正常网页完成验证，保存后再检查好友与发送状态。不会自动解验证码或反复尝试登录。 |

发送前会保留一条预约记录。若进程在点击发送附近崩溃，宁可要求人工核验，也不把不确定的请求重新自动发送。这是在网络和网页自动化条件下的取舍，不是“绝不会漏发/绝不会重发”的承诺。原有草稿会保留，出现草稿不一致时不会覆盖后发送。

“没有观察到发信请求”也属于不确定结果，可能是网页接口变化或观察器失效。它不会清除预约记录，也不会触发批量补发。先核对聊天记录，再单独手动处理。

消息为每天相同的 `1` 时，普通聊天以本次服务器消息编号核对重新加载后的历史，旧气泡或数量变化不能证明新消息成功。火花是否延续仍以抖音客户端显示为准。

HTTP 200 只表示请求得到响应。仅含 `decision`、无法解读的响应、缺少明确业务成功或消息编号、观察器不可用、只有本地气泡，都保留为待核验。旧账本即使标为“strong”，回执证据不足时也不再计入确认数；当天自动派发与未发送批次会跳过这些记录，避免降级后重复发送。先检查双方 App 聊天记录并完成平台要求的正常验证，不绕过响应决策。

平台若返回仅自己可见、消息检查失败或对方限制，停止该账号发送，不能靠忽略状态、修改请求参数或反复补发解决。历史 Creator 通道仍保留作兼容选项，不能用它的本地消息气泡代替普通聊天的收件验收。

普通聊天会等待联系人名称加载，核对唯一的选中会话和右侧标题，保留已有草稿，并等待页面自己的发送控件进入可发送状态；点击的是该输入框对应的图标控件。内部 `/ordinary/prepare-check` 可对一个已保存目标走完准备流程，保留预期草稿，但不点击发送、不记录发送预约。它与正式派发一样需要内部令牌和持锁租约，不能传入任意账号、目标或脚本。

正式发送与准备检查统一使用禁用 HTTP 缓存的资源加载方式，以避免持久化资料中的旧资源与当前页面不一致。请求原样交给正常网页处理，不修改 Cookie、认证头或平台参数。Playwright 的这一缓存行为见[官方文档](https://playwright.dev/python/docs/api/class-browsercontext#browser-context-route)。显式准备检查失败时可在本机 `logs/diagnostics/` 留下私人页面截图；它不属于脱敏诊断，不能上传。

发送浏览器退出后才启动独立复核浏览器，同一时刻只运行一个任务浏览器，避免桌面容器进程数达到上限。多位好友逐个处理；账号资料和联系人仍逐次核验。复核还检查消息创建时间，旧编号不能用于确认新尝试。若服务器已返回成功，但复核浏览器失败，保留回执和预约；恢复后只读复核原编号，不重新发送。

## 可分享的诊断

```sh
python3 deploy/doctor.py
python3 deploy/doctor.py --output state/doctor.json
```

报告只含服务状态、数量、定时规则和失败类别，不含账号昵称、好友名称、聊天内容、Cookie、认证头和错误堆栈。提交问题时优先使用该报告。私人日志、浏览器目录、截图和 `.env` 不属于这份脱敏报告。

## 升级与恢复

升级前在本机备份 `.env`、运行时 JSON 和 `state/`，保管好备份；不要上传到公开仓库。暂停调度后更新源代码，检查 `docker compose config --quiet`，重建并重启管理与登录服务，再核对账号、联系人和计划，最后恢复调度。

登录服务内部令牌保存在 `state/login-api/token`，管理服务只读挂载。更换令牌时应先停登录工作区、保留旧文件本机备份、移走该令牌并重新启动登录服务和管理服务；不要把令牌发给他人。调试 API 默认关闭，开启也需要内部令牌。原先完整网络请求头/响应抓取接口已移除。

若调度状态文件损坏，服务会停止派发以避免重发。先备份损坏文件并核对当天聊天和发送记录，再恢复可验证的备份；不要把删除状态文件当作日常重试方法。

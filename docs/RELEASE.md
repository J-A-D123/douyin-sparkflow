# 发布与验收

此版本是基于上游的可靠性改进。保留根目录 LICENSE、NOTICE 和原有第三方许可，不把上游代码改标为其他许可证。当前许可证为 PolyForm Noncommercial 1.0.0；仓库公开与许可证范围是两件分别需要说明的事。

## 2026-11-02 本机验收记录

一个本人账号向一位已配置好友通过普通聊天 UI 发送一条预期文字，本人确认 App 收到。正常网页的明确成功响应包含服务器消息编号；随后在独立上下文只读复核同一编号、正文、发送方、创建时间及可见范围，补记确认结果，没有重发。

发送后曾因两个 Chromium 同时运行而触及桌面容器的进程数上限；现改为先关闭发送浏览器再复核，隔离测试覆盖这一顺序。最终源码通过 176 项无账号测试。修复后的只读复核未再次发信。同日用户新增账号并反馈成功，后续本机账本为 2 个账号、3 个目标，均有网页发送确认。首条有本人明确的 App 收件确认；新增记录不等于已逐一核对全部收件方 App。次日调度、10 个账号及连续七天仍需独立验证；火花结果以 App 为准，调度当前状态以各自管理面板为准。

## 发布前自动验证

在一个不包含私人配置的干净检出目录，使用 Python 3.10+：

```sh
cd DouYinSparkFlow
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
python -m playwright install chromium --only-shell
python -m unittest discover -s tests -v
cd ..
python deploy/check-release.py
docker compose config --quiet
```

Windows 使用 `.venv\Scripts\Activate.ps1` 激活虚拟环境。Linux CI 安装浏览器时还使用 `--with-deps`。CI 定义覆盖 Python 3.10、3.11、3.12；只有对应 GitHub 运行真正通过后，才将该矩阵标记为已验证。当前机器上通过测试不能代替 Windows/macOS/Linux 全部实机结果。

`check-release.py` 检查 Git 将发布的文件、常见凭据形态及本机运行时凭据是否误入源码，不打印凭据值。它不能替代人工检查图片、截图、文档和提交历史。首次发布还应检查 `git diff`、`git status`、所有待发布图片，以及已有 Git 历史；不要使用 `git add .` 来代替逐项核对。

GitHub 仅运行无账号 CI，不执行真实发信任务，不读取账号 Secret，不上传私人日志。Dependabot 只提出依赖更新，更新仍须经过测试和审查。

在 Git 检出目录执行 `python deploy/build-release.py` 可生成 `output/SparkFlow-source.zip`。打包器再次检查待打包的实际内容，排除被忽略的运行资料，并加入每个源文件的 SHA-256 清单。此包用于代码审查；从 ZIP 解压的目录不包含 Git 元数据，发布检查和再次打包应在自己的 Git 检出目录执行。

## 必须独立记录的实机验收

1. 一个本人账号正常登录、保存、重启后仍能被核验；账号不一致时保存被拒绝。
2. 一位明确选定的好友收到一条预期文字；双方核对收件记录。相同文案第二天仍可发送，旧气泡不会被当作新成功。
3. 连续两位好友切换正确，没有隐藏列表超时或错发。
4. 同日重启及重复点击后，已确认目标不被自动重复发送。
5. 在发送前、点击后、回执前模拟进程退出，界面显示待核验而非虚假成功。
6. 电脑休眠、调度器暂停、登录过期、网络失败、状态文件损坏均有可理解的状态和恢复步骤。
7. 至少连续七天记录计划时间、实际触发、账号状态、确认数和客户端火花结果，再考虑给版本增加“稳定”说明。

测试记录中写清版本、系统架构、浏览器/Playwright 版本和日期，只写匿名编号或数量。没有实际验证的项目保留为未通过，不能用单元测试数量、HTTP 200 或日志中的“已点击发送”代替验收。

## 发布步骤

先准备自己的 Fork 或明确的发布仓库；保留上游来源。通过 CI、源码隐私检查及适用的实机验收后，审查提交差异，再创建发布记录。发布说明分别列出修复、验证范围和未解决问题。发布源代码包时排除 `.git`、`.env`、`state/`、运行时 JSON、浏览器目录和私人日志。

账号 Cookie、浏览器资料和运行日志不随源码包发布。备份恢复使用本地私有流程。对于旧版本曾经误提交过的凭据，单纯增加 `.gitignore` 并不能撤回历史，应先轮换凭据，再处理仓库历史。
